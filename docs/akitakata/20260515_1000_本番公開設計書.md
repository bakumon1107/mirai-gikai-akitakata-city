## フェーズ1: Supabase 本番プロジェクト作成

### 1-1. プロジェクト作成

1. https://supabase.com にログイン（組織: `bakumon1107` を推奨）
2. 「New project」→ 以下の設定で作成

| 設定項目 | 推奨値 |
|---------|--------|
| Name | `mirai-gikai-akitakata` |
| Region | `Northeast Asia (Tokyo)` |
| Database Password | 強いパスワードを生成して保存 |
| Plan | **Free**（月50万行まで無料） |

3. 作成後、「Project Settings > API」から以下を控える

| 変数名 | 取得場所 |
|--------|---------|
| `SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL（同じ値） |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role（非公開キー） |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public（公開キー） |

### 1-2. マイグレーション実行

ローカルから本番 Supabase に対して全87マイグレーションを適用する。

```bash
# supabase/config.toml に本番プロジェクト ID を設定
# project_id = "mirai-gikai"  ← Supabase ダッシュボードの URL から取得

# 本番 DB にリンク（接続パスワードを入力）
npx supabase link --project-ref <PROJECT_REF>

# 全マイグレーション適用
npx supabase db push
```

> **注意**: ローカルの `seed.sql` は開発用データ（admin@example.com 等）を含むため、
> 本番では `--skip-seed` を付けて実行する。

### 1-3. Storage バケット確認

マイグレーションで自動作成されるが、Supabase ダッシュボード「Storage」で
以下のバケットが存在することを確認する。

- `bill-thumbnails`
- `bill-contents`

## フェーズ2: Vercel プロジェクト作成

### 2-1. プロジェクト作成

1. https://vercel.com にログイン
2. 「Add New > Project」→ GitHub リポジトリ `bakumon1107/mirai-gikai-akitakata-city` を選択
3. ビルド設定を以下の通り設定（monorepo のため `web/` ディレクトリ指定が必要）

| 設定項目 | 値 |
|---------|---|
| Framework Preset | Nexdt.js |
| Root Directory | `web` |
| Build Command | `cd .. && pnpm build --filter web` |
| Output Directory | `.next`（デフォルト） |
| Install Command | `cd .. && pnpm install --frozen-lockfile` |

### 2-2. 環境変数設定

Vercel ダッシュボード「Settings > Environment Variables」で以下を設定する。
すべて **Production / Preview / Development** 全環境に設定する（Productionのみ必須）。

| 変数名 | 値 | 備考 |
|--------|---|------|
| `SUPABASE_URL` | フェーズ1で取得した本番URL | |
| `SUPABASE_SERVICE_ROLE_KEY` | 本番 service_role キー | **Sensitive** |
| `NEXT_PUBLIC_SUPABASE_URL` | 本番URL（SUPABASE_URLと同じ） | |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 本番 anon キー | |
| `REVALIDATE_SECRET` | ランダム文字列（32文字以上） | `openssl rand -hex 32` で生成 |
| `NEXT_PUBLIC_WEB_URL` | `https://（公開ドメイン）` | Vercelドメインで仮設定してOK |
| `ADMIN_URL` | `""` | Admin未デプロイのため空文字 |
| `AI_GATEWAY_API_KEY` | ※後述 | AIチャット有効化時に設定 |
| `BASIC_AUTH_USER` | ソフトローンチ中のみ設定 | フェーズ5完了後に削除 |
| `BASIC_AUTH_PASSWORD` | ソフトローンチ中のみ設定 | フェーズ5完了後に削除 |

> **AIチャット**: `siteConfig.features.aiChat` が `true` の場合のみ `AI_GATEWAY_API_KEY` が必要。
> 初回公開はコスト管理のため `aiChat: false` で公開することを推奨。

## フェーズ4: 本番データ投入

### 4-1. council_session 作成

ローカルで作成した「令和8年第1回定例会」レコードを本番 Supabase に投入する。

```bash
# packages/seed/akitakata/ 配下にスクリプトを作成（または curl で直接投入）
SUPABASE_URL=<本番URL>
SERVICE_KEY=<本番SERVICE_ROLE_KEY>

curl -s -X POST "$SUPABASE_URL/rest/v1/council_sessions" \
  -H "apikey: $SERVICE_KEY" \
  -H "Authorization: Bearer $SERVICE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "令和8年第1回定例会",
    "slug": "r8-1",
    "start_date": "2026-03-01",
    "end_date": "2026-03-20",
    "city": "安芸高田市"
  }'
```

> **注意**: ローカルのセッションIDと本番のセッションIDは異なる（UUID）。
> `general_questions` 投入時に本番で発行された `id` を使うこと。

### 4-2. general_questions 移行

ローカルの14件（第1日7名・第2日7名）を本番に投入する。
`publish_status = 'published'` で投入すること。

**方法A: seed-from-sections.ts を本番向けに実行**

```bash
cd packages/seed/akitakata

# .env.production に本番キーを設定して実行
SUPABASE_URL=<本番URL> \
SUPABASE_SERVICE_ROLE_KEY=<本番SERVICE_ROLE_KEY> \
npx tsx seed-from-sections.ts r8-1 1
# → 第1日 7名を投入

npx tsx seed-from-sections.ts r8-1 2
# → 第2日 7名を投入
```

**方法B: pg_dump / pg_restore（より確実）**

```bash
# ローカルから general_questions だけエクスポート
npx supabase db dump --local --data-only -t general_questions > /tmp/gq_export.sql

# 本番に投入（接続文字列はSupabaseダッシュボード「Database > Connection string」から取得）
psql "<本番接続文字列>" < /tmp/gq_export.sql
```

> **推奨**: 方法Aでseed-from-sections.tsを使うと、OCRテキストを再AIパースするため
> コストがかかる。方法BでDB直接コピーが最も効率的。
> ただし、ローカルのcouncil_session_idと本番のIDが一致しないため、
> council_session_idのみ本番IDに置換してからインポートする必要がある。

### 4-3. データ確認

投入後、本番URLで以下を確認する。

```bash
SUPABASE_URL=<本番URL>
SERVICE_KEY=<本番SERVICE_ROLE_KEY>

# 投入件数確認
curl -s "$SUPABASE_URL/rest/v1/general_questions?select=questioner_name,publish_status" \
  -H "apikey: $SERVICE_KEY" \
  -H "Authorization: Bearer $SERVICE_KEY"
```
