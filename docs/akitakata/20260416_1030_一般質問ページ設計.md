# 一般質問ページ 設計書

作成日: 2026-04-16  
更新日: 2026-04-16（レーダーチャート廃止 → スタンス分析に変更）

## 概要

安芸高田市議会の一般質問を議員ごとに閲覧できるページ。
質問通告・質疑応答の概要・詳細なやりとりを確認でき、
質問者のスタンス分析（AI生成）を詳細ページ末尾に表示する。

参照元:
- 通告一覧: https://www.akitakata.jp/ja/parliament/situmon/2601-copy-5/
- 速報版 PDF（令和8年第1回 3/5）: sokuhou-han-aki-takadashi-rei-wa-8nen-daiikkai-teireikai-2r080305.pdf
- 過去PDF（令和7年第4回 12/12, 12/15）も同形式

---

## データ構造

### PDF から得られる情報

速報版議事録 PDF の構造（一問一答方式）:

```
議員 → 大枠テーマの宣言
  └─ (1) 質問テキスト
     └─ 市長/担当部長 → 答弁テキスト
        └─ 議員 → 再質問
           └─ 市長/担当部長 → 再答弁
           ... (最大 30 分)
```

例（令和8年第1回定例会 3/5）:
- **新田議員**: 大枠4点（ネーミングライツ / 高齢者施設 / 道路インフラ / 農業振興）
- **益田議員**: 過疎地域持続的発展計画 / バイオマス発電所 等
- 他: 山本議員 等（3/9 分は未取得）

## DB テーブル設計

### `general_questions`（一般質問セッション単位）

```sql
create table general_questions (
  id uuid primary key default gen_random_uuid(),
  council_session_id uuid not null references council_sessions(id) on delete cascade,
  session_day int not null,          -- 1, 2, ... (第1日目, 第2日目)
  questioner_name text not null,     -- 議員名（例: "新田和明"）
  questioner_number int,             -- 議席番号（例: 8）
  topics jsonb not null default '[]',
  -- topics 構造:
  -- [
  --   {
  --     "index": 1,
  --     "title": "ネーミングライツ導入の課題と今後の展開",
  --     "question_summary": "...",
  --     "answer_summary": "...",
  --     "exchanges": [
  --       { "speaker": "questioner", "name": "新田和明", "text": "..." },
  --       { "speaker": "answerer", "name": "藤本市長", "role": "市長", "text": "..." },
  --       ...
  --     ]
  --   }
  -- ]
  overall_summary text,              -- 質問全体を通じた2〜3文の総括
  questioner_stance text,            -- 建設的提案型 | 批判追及型 | 情報確認型 | 課題提起型
  stance_analysis text,              -- 質問者の姿勢・スタンスに対する分析（2〜3文）
  pdf_url text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (council_session_id, session_day, questioner_name)
);
alter table general_questions enable row level security;
create index general_questions_council_session_id_idx on general_questions(council_session_id);
```

## スタンス分析設計

### スタンス分類（4種）

| スタンス | 説明 | バッジ色 |
|---|---|---|
| **建設的提案型** | 行政方針に概ね賛同し、改善提案を行う | 緑 (`bg-green-100 text-green-700`) |
| **批判追及型** | 行政の問題点を指摘・追及する | 赤 (`bg-red-100 text-red-700`) |
| **情報確認型** | 政策の内容・現状を確認・把握する | 青 (`bg-blue-100 text-blue-700`) |
| **課題提起型** | 新たな課題を提起し議論を促す | オレンジ (`bg-orange-100 text-orange-700`) |

### AI 生成プロンプト概要

シードスクリプト（`seed-general-questions.ts`）の `buildEnrichedPrompt()` で以下を生成:

```json
{
  "overall_summary": "質問全体を通じた2〜3文の総括",
  "questioner_stance": "建設的提案型 | 批判追及型 | 情報確認型 | 課題提起型",
  "stance_analysis": "質問者の姿勢・スタンスに対する2〜3文の分析",
  "topics": [
    {
      "index": 1,
      "title": "テーマタイトル",
      "question_summary": "質問概要",
      "answer_summary": "答弁概要",
      "exchanges": [
        { "speaker": "questioner", "name": "新田和明", "text": "発言要約" },
        { "speaker": "answerer", "name": "藤本市長", "role": "市長", "text": "答弁要約" }
      ]
    }
  ]
}
```

### 表示ロジック

- `questioner_stance` が null でも `stance_analysis` があれば表示
- `questioner_stance` に対応する `STANCE_CONFIG` が未定義の場合はグレーのデフォルトバッジ

## シードスクリプト

`packages/seed/akitakata/seed-general-questions.ts`

```
1. PDFをテキスト抽出（pdftotext -layout）
2. gqText: "日程第2 一般質問" 以降を切り出し
3. splitByQuestioner(gqText) で議員ごとのセクションに分割
4. buildEnrichedPrompt() でAI構造化（exchanges + 総括 + スタンス分析）
5. general_questions テーブルへ upsert
```

```bash
# 使い方
pdftotext -layout <pdf> /tmp/gijiroku.txt
npx tsx --env-file=../../.env akitakata/seed-general-questions.ts \
  /tmp/r8-1-0305.txt r8-1 1
```

## 備考

- 福岡市版の「予算ページ」が2列カードレイアウト → 同じ構造を採用
- 議員バッジはタグ形式（`BillTag` と同様の見た目）で統一感を持たせる
- チャット形式の詳細表示: 質問者は左側（青アバター「質」）、答弁者は右側（暖色アバター「答」）
- レーダーチャートは「情報が少なすぎる」ため廃止。スタンス分析に置き換えた
