## 2. PDF読み取りツール比較（pdftotext vs markitdown）

### 2-1. 比較目的

条例の新旧対照表（2カラムレイアウト）を含む日本語PDF対しての抽出品質を比較する。

### 2-2. 比較対象

| ツール | 種別 | 特徴 |
|--------|------|------|
| `pdftotext`（poppler-utils） | CLI | 現在使用中。高速・シンプル。テキストを行順に抽出 |
| `markitdown`（Microsoft OSS） | Python | Markdownに変換。テーブル構造を保持できる可能性あり |

### 2-3. 比較議案

**議案第5号**（安芸高田市特別職の職員で常勤のものの給与及び旅費に関する条例の一部を改正する条例）を1議案のみ使用。

理由: 新旧対照表を含む比較的短い条例改正案のため評価しやすい。

### 2-4. 評価基準

| 観点 | 評価方法 |
|------|---------|
| 新旧対照表の分離精度 | 改正前・改正後が混在せずに読み取れるか |
| 日本語テキストの正確さ | 文字化け・欠落の有無 |
| 構造の保持 | 見出し・表・箇条書きの再現度 |
| 処理速度 | 実行時間の計測 |
| 要約精度への影響 | 同一プロンプトでAI要約させたとき、markitdownの方が良いアウトプットが出るか |

### 2-5. 比較結果（議案第5号で実施済み）

| 観点 | pdftotext | markitdown v0.1.5 |
|------|-----------|-------------------|
| 新旧対照表の可読性 | ○ テキストが混じるが読める | △ 不要な空列が大量生成されて乱雑 |
| 日本語テキスト正確さ | ○ 正確 | ○ 正確 |
| 処理速度 | **0.05s** | 0.6s (CPU 4.5s) |
| AI要約への適性 | ◎ そのまま渡せる | △ 空セル多く雑音になる |

**結論: pdftotext を採用。** markitdown は日本語の複数カラムPDF（新旧対照表）では
PDF内の列を過剰検出しMarkdownテーブルに変換するため、逆に可読性が下がる。
条例改正系の議案においては pdftotext の方が優れている。

markitdown のライセンス: **MIT License** (Copyright Microsoft Corporation)
→ 開発ツールとして使用のみで再配布なし。今回はプロダクトに組み込まない。

## 3. bill_contents 生成方針

### 3-1. 構成

```
title   : 市民向けの分かりやすいタイトル（30文字以内）
summary : 1〜2文の概要（ツイート程度）
content : Markdown形式の詳細解説
  - どんな議案？
  - 具体的に何が変わる？
  - 市民への影響は？
  - 施行日
```

### 3-2. 議案の分類と処理方針

| 分類 | 対象 | 処理方針 |
|------|------|---------|
| 条例改正（技術的） | 第2・4・5・6・8号等 | PDF全文を読んでAI要約 |
| 条例改正（施策的） | 第3・9・10・12・13・15・37号 | PDF全文を読んでAI要約 |
| 予算・補正予算 | 第16〜22号 | 予算規模・主な事業をAIが要約 |
| 各特別会計予算 | 第23〜36号 | 会計名・規模のみ簡略要約 |
| 議会発議 | 発議第2・3号 | PDF全文を読んでAI要約 |

### 3-3. AIプロンプト（bill_contents生成用）

```
以下は安芸高田市議会に提出された議案のテキストです。
市民にわかりやすく解説するbill_contentsを作成してください。

## 出力形式（JSONで出力すること）
{
  "title": "市民向けタイトル（30文字以内）",
  "summary": "1〜2文の概要（ツイート程度）",
  "content": "# タイトル\n## どんな議案？\n...\n## 施行日\n..."
}

## 議案テキスト
<PDF全文>
```

## 5. タグ自動評価ロジック

### 5-1. 方針

Fukuoka版の `auto-feature-evaluator` パターンを参考に、**タグ割り当て専用のスクリプト**を実装する。  
一時的なスクリプト（`packages/seed/akitakata/` 以下）として実装し、seed完了後に実行する。

### 5-2. 評価プロンプト

```
あなたは安芸高田市議会の議案を分析するアシスタントです。
以下の議案に対して、適切なタグを選択してください。

## 選択可能なタグ
- 予算・財政💰: 一般会計・特別会計の予算・補正予算
- 条例改正📜: 既存条例の一部改正
- 福祉・医療🏥: 介護保険・国民健康保険・高齢者医療など
- 教育📚: 学校・給食センター・教育支援など
- 住宅・まちづくり🏠: 定住促進住宅・有住宅・まちづくりなど
- 移住・定住🏡: 移住支援・起業支援・定住促進など
- 農林業・環境🌿: 農業・林業・環境整備など
- 道路・インフラ🛣️: 市道認定・ダム・公共施設など
- 組織・人事👥: 職員給与・特別職報酬・附属機関など
- 議員提出📣: 議会発議（意見書・議員条例）

## ルール
- 1議案に複数タグ付与可（最大3つ）
- 必ず1つ以上付与すること
- 予算議案は必ず「予算・財政💰」を付与する
- 条例改正を含む場合は「条例改正📜」を付与する
- 発議には「議員提出📣」を必ず付与する

## 出力形式（JSONのみ出力）
{"tags": ["タグラベル1", "タグラベル2"]}

## 議案情報
名称: <議案名>
内容（要約）: <bill_contentsのsummary>
```

### 5-3. 実装方針

- 既存の bill_contents.summary + 議案名をインプットとし、タグを判定
- Anthropic SDK（TypeScript）で直接呼び出す（Fukuoka版のCLI呼び出しではなく）
- `packages/seed/akitakata/tag-evaluator.ts` として実装

## 6. 実装ステップ

```
Step 1: PDF比較（markitdown vs pdftotext）
  - 議案第5号PDFで両ツールを実行
  - 出力内容を比較
  - 品質が良い方を以降の処理に使用する

Step 2: 全議案のPDF取得 & bill_contents生成
  - 未登録議案のPDFを取得してAIで要約
  - 既存4議案にも bill_contents を追加（今後対応 or 今回実施）
  - publish_status = 'published' で登録

Step 3: タグのDB登録
  - `tags` テーブルに10タグを INSERT

Step 4: タグ自動評価スクリプトの実装・実行
  - tag-evaluator.ts 実装
  - 全 published 議案に対して実行
  - `bills_tags` テーブルに結果を INSERT
```
